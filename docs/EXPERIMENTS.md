# Experiment protocols

A denotes Aariz and I denotes ISBI 2015. In S→T, S is the training dataset and T is the evaluation dataset. The development matrix evaluates A→A and I→A on Aariz valid, and A→I and I→I on ISBI test1. Every standard training run also saves predictions for Aariz test and ISBI test2.

## Main configuration

- Pretrained ResNet-34 encoder, U-Net decoder, 19 heatmaps.
- Soft-argmax with pixel-centre coordinates and a learned positive heatmap multiplier.
- L1 coordinate loss in network-input pixels.
- 512 × 512 aspect-preserving input; cached image long side 1024.
- 60 epochs, batch size 6, AdamW, maximum learning rate 0.001, weight decay 0.0001, OneCycleLR.
- Scale sampled log-uniformly between 1/1.6 and 1.6, rotation ±12°, translation ±10% of each input dimension.
- Gamma between 1/1.5 and 1.5, contrast 0.75–1.25, brightness ±0.1; inversion disabled.
- Seeds 0, 1, 2. Inference uses the deterministic base transform.

The same affine mapping samples each image, transforms its landmark supervision, and restores predicted coordinates. There is no additional pairwise consistency loss in the main configuration.

## Launcher suites

| Suite | Tags | Purpose |
|---|---|---|
| main | s1_letter | RandCeph in both source directions |
| controls | pilot_squash, abl_letter_noaug | Same detector without augmentation, with square or aspect-preserving inputs |
| ablations | abl_squash_aug, abl_scratch, abl_convnext | Square input with augmentation, random initialization, and ConvNeXt-Tiny encoder |
| joint | s1_letter / joint | Aariz train plus four repetitions of ISBI train |
| lodo | s1_letter / lodo:<device> | Hold out each of the seven Aariz devices |

The launcher provides commands for all selected source/seed combinations. The manuscript's reported coverage varies by experiment; new combinations generated by the launcher are additional runs, not pre-existing measurements.

The LODO splitter pools Aariz train/valid/test by device, holds out one device, and reserves the first 15% of the permuted remaining pool for in-domain validation. It follows the benchmark split definition implemented in `train_lm.py`.

## Evaluation scope

Source-only runs fit model parameters with source labels. Development included inspection of transfer performance, as described in the manuscript; the independent split results should be interpreted separately. Joint training uses labels from both datasets.

Target-offset calibration in `analysis.py` uses target labels and cross-fitting. Its results have a different supervision condition from the source-only matrix. Anatomical scale normalization is a sensitivity analysis of measurement units; the main MRE uses listed pixel spacing.

`code/ttc.py` implements the separate test-time canonicalization experiment. The `--view canon`, `--view phys`, and `--unlab` options in the training script are experimental variants, not the main RandCeph configuration. Refer to the saved run arguments to distinguish them.

## Outputs required by analysis

The complete analysis relies on source image caches, the audit CSVs, main and control predictions for both sources, joint predictions, and LODO predictions. Run preparation and audit first, then the required training suites, then evaluation, analysis, and figures. Partial run collections can produce incomplete summaries or missing-input errors.

This source release does not contain the original training environment lockfile or trained artifacts. CPU validation covers source syntax, metric conventions, and experiment-command generation; GPU training and numerical reproduction require the datasets and CUDA environment.
